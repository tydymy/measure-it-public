# Analysis plan: Phase 3 measurement evidence (phenotype_signal_strength and the Phase 3 table)

_Verbatim copy, made 2026-09-23 during integration, of the analysis plan in the module docstring of `src/measure_it/measurements/phenotype_evidence.py`. The plan was written there before any Phase 3 verdict, table or figure was computed (the contributor could not create a docs/*.md file at the time; see DEVIATIONS). The docstring stays authoritative; this file adds nothing and changes nothing. Results: `results/PHASE3_MEASUREMENT_EVIDENCE.md` (generated by the module). Deviations recorded after the plan are listed at the end, copied from `DEVIATIONS` in the same module._

## Module summary (docstring header)

```text
Phase 3 measurement evidence: what could make the phenotype visible (SPEC Phase 3).

Fills `phenotype_signal_strength` (and a separate `molecular_context__*` column group) in `measurement_registry` and
`condition_measurement_evidence`, and builds the Phase 3 table for the four demo phenotypes. No model is fitted and
no person-level statistic is computed here: the module re-reads the aggregate results that the NHANES and Stanford
producers already wrote, and `measurable_biology` from the molecular-coherence step.

Run: `uv run python -m measure_it.measurements.phenotype_evidence` (rebuilds evidence.py outputs, then Phase 3).
```

## Plan (verbatim)

```text
ANALYSIS PLAN (written 2026-09-23, BEFORE any phase3 verdict, table or figure was computed)
==========================================================================================
The producer tables and their reports (results/WEARABLE_NHANES_RESULTS.md, WEARABLE_STANFORD_RESULTS.md,
MOLECULAR_COHERENCE.md) already existed and were read while writing this plan, so the rules are chosen from stated
principles (conventional thresholds; the producers' own pre-specified tests), not tuned to give particular verdicts.
Deviations after this point are listed in DEVIATIONS at the bottom of this module. (The plan lives here because the
build harness would not let this contributor write a new docs/*.md file; see the final report.)

1. Questions
   Q1 phenotype_signal_strength: for each measurement class/bundle, condition and demo phenotype, do the public
      person-level analyses already run in this build (NHANES 2011-2014 wrist accelerometry; Stanford consumer-wearable
      resting HR and steps) show a measurable group difference, and how strong is the label behind it?
   Q2 Phase 3 table: for orthostatic/autonomic dysfunction; activity intolerance / post-exertional pattern;
      sleep/circadian disruption; post-infection physiological recovery: observable signals, candidate classes and
      bundles, evidence per source (public patient datasets, ClinicalTrials.gov, NIH RePORTER, openFDA, molecular
      context) and the five SPEC dimensions kept separate.
   Q3 attach measurable_biology as its own column group, never blended into another dimension.
   A stronger label that exists but was not analysed (e.g. NHANES SLQ050 trouble sleeping / SLQ060 sleep disorder)
   is reported as a gap, not filled.

2. Inputs: phenotype_signatures__nhanes (14 phenotypes x 26 features, age/sex-adjusted SD differences, BH q per
   phenotype, `underpowered`); results/tables/nhanes_increments.csv, nhanes_model_performance.csv,
   nhanes_permutation_null.csv; phenotype_signatures__stanford; results/tables/stanford_uwakwe_model_increments.csv,
   stanford_uwakwe_model_performance.csv, stanford_acute_detection.csv (+ stanford_acute_trajectory_by_day.csv and
   stanford_acute_endpoints.csv for descriptive notes only); measurable_biology; measurement_registry,
   condition_measurement_evidence, measurement_phenotype_axis_map, phenotype_axes; modality_inventory__mapmecfs.
   Audit traps honoured: NHANES has no HR/HRV (exam pulse is not wearable HR), sleep features are an algorithm proxy,
   ME/CFS / Long COVID / POTS / EDS are not asked about, rx reason codes are 2013-14 only; only Uwakwe 2025 carries a
   (self-reported) Long COVID label, it released no steps and no infection date; Mishra 2020 / Alavi 2022 are acute
   COVID-19 cohorts, NOT Long COVID; `rhr_rmssd_daily` is day-to-day variability of daily resting HR, NOT HRV;
   MapMECFS actigraphy/HRV/tilt/CPET person-level files are gated (open data group-labelled only).

3. Signal result = (dataset, label, class, feature scope). Components: dataset; label id + producer label basis;
   label_class; n cases/controls; features tested; best effect (largest |effect| among q < 0.05 features, else
   largest overall) with measure, 95% CI, feature; n features q < 0.05; n features q < 0.05 AND |effect| >= 0.2
   (SD-unit measures only); model metric/estimate/CI/permutation p/status; underpowered flag; verdict; signature ids.
   NHANES feature -> class: sleep_objective = the 6 sleep-proxy features; accelerometry = the other 20. Families:
   see NHANES_FAMILY. q-values are the producer's BH over all 26 features (subset counts are conservative).
   Stanford Uwakwe: 7 whole-record resting-HR features (primary unadjusted Hedges' g; adjusted rows = sensitivity).
   Stanford acute: tested endpoints rhr_acute_elevation_fraction_vs_placebo, rhr_mean_z_days0_14_vs_placebo ->
   wearable_heart_rate; steps_mean_z_days0_14_vs_placebo -> accelerometry; descriptive rows are notes only.
   Model evidence = the producer's pre-specified primary model: NHANES Test 1 Delta AUROC (demographics + wearable
   minus demographics, pen_lr, cv_5x5) with status positive iff CI low > 0 AND wearable-only label-permutation
   p <= 0.05, negative iff CI high < 0, else null (Test 2 reported, used only in a sensitivity verdict); Stanford Long
   COVID Delta AUROC (l2_logistic) with the wearable-block permutation p; Stanford acute window-A onset-vs-placebo
   AUROC (accelerometry row: the pre-specified L2 model on mean/max RHR z + mean step z; wearable_heart_rate row: the
   pre-specified model-free mean RHR z), positive iff CI low > 0.5 AND p <= 0.05. Signature-only labels: not_tested.
   VERDICT (a = n features with q < 0.05 and, for SD-unit measures, |effect| >= 0.2):
     supported = a >= 1, model positive or not_tested, label not underpowered;
     mixed     = a >= 1 with model null/negative or label underpowered; or a = 0 with model positive;
     null      = a = 0 and model not positive;
     not_observable_in_public_data / not_analysed -> dimension value UNKNOWN / NOT AVAILABLE (never 0 or "null").
   Label strength is a separate component, never folded into the verdict. Label classes, strongest first:
   clinical_diagnosis (none available) > self_reported_condition_case_definition (Uwakwe) >
   self_reported_symptom_or_function = questionnaire_screen > constructed_proxy = rx_reason_code;
   acute_infection_episode and linked_death_record are not condition labels.

4. Condition fill. Reference labels: long_covid <- Uwakwe (wearable_heart_rate); me_cfs <- NHANES mecfs_like_proxy
   (accelerometry, sleep_objective; proxy variants = sensitivity labels); fibromyalgia <- rx_fibromyalgia; migraine
   <- rx_migraine; ibs <- rx_ibs. Everything else not_observable_in_public_data, except not_analysed where
   person-level data for the class sit beside a label (NHANES labs -> blood_biomarkers for me_cfs, fibromyalgia,
   migraine, ibs; MapMECFS participant-linked omics -> transcriptomics/proteomics/metabolomics for me_cfs). Acute
   COVID-19 results are NEVER a Long COVID verdict; they go to `__adjacent_evidence` for long_covid and
   post_infectious_syndrome. Bundles: highest member verdict (supported > mixed > null > UNKNOWN) with every member in
   `__by_member`. Registry: highest verdict over target-condition reference labels, with `__by_condition`, and
   non-condition labels (functional limitation, fatigue, fair/poor health, PHQ-9, rx insomnia, rx myalgia, acute
   cohort, mortality positive control) in `__non_condition_labels`, never merged into the value.

5. Molecular context (`molecular_context__*`): best measurable_biology support_status over linked systems
   (multi_source > single_source > literature_only > study_catalogue_evidence > not_supported > too_few_genes >
   no_molecular_data), the same on support_status_without_flagged_sources, systems with sources/flags, molbio: ids;
   `no_system_link` for classes without a curated system link; bundles = union of members. Condition-level
   enrichment, not person-linked, not mechanism; not used in any other dimension or in ordering.

6. Phase 3 table (phenotype x technology). Axes and scopes in PHENOTYPES. Technologies = classes linked to the axes
   in measurement_phenotype_axis_map + curated additions (labelled) + bundles with >= 1 member. Reference label per
   phenotype x class in PHENOTYPES[...]["reference"]; all other relevant labels in `__other_labels`; every other
   phenotype x class is not_observable_in_public_data with a reason. Dimensions: phenotype_signal_strength =
   reference verdict; measurement_evidence_strength = highest over the 4 demo conditions of the existing
   one-condition tier (>= 10 high, 3-9 moderate, 1-2 low, 0 none) on the SPECIFIC-TERM objective-trial count (so
   dysautonomia's broad 'autonomic dysfunction' links do not set it), every per-condition tier kept;
   technology_maturity, regulatory_visibility, deployment_complexity = registry values. No composite, no cross-
   dimension ranking; rows are listed classes first, then bundles, alphabetically.

7. Query layer: discover_candidate_measurements carries the condition-level phenotype signal inside `dimensions` and
   molecular_context as a separate key; ORDERING RULE UNCHANGED (phenotype_signal_strength is shown, not used to
   order). `phenotype` also accepts the four demo phenotypes (exact id / label / listed alias; an exact axis match
   still wins; no fuzzy match). get_measurement_evidence adds the signal results and molecular context. New
   get_phenotype_measurement_evidence(phenotype) returns the Phase 3 block or UNKNOWN with a reason.

8. Controls: rule sanity checks fixed in advance: NHANES mortality positive control -> supported; rx_ibs (12 cases)
   not supported; Uwakwe Long COVID -> null. Threshold sensitivity (q < 0.10 without effect floor; q < 0.05 with a
   0.3 floor); model-criterion sensitivity (NHANES Test 2 instead of Test 1); label sensitivity (proxy variants,
   Uwakwe age/sex-adjusted). Changed verdicts are counted and reported.

9. Outputs: results/tables/phase3_measurement_evidence.csv, phase3_signal_results.csv, phase3_condition_signal.csv,
   phase3_phenotype_summary.csv, phase3_verdict_sensitivity.csv; processed tables measurement_phenotype_signal and
   phase3_measurement_evidence (object ids `measurement_signal:<dataset>|<label>|<class>|<scope>`,
   `phenotype_evidence:<phenotype>|<measurement>`); results/PHASE3_MEASUREMENT_EVIDENCE.md written by write_report()
   from those tables; draft figures results/figures/drafts/phase3_*.png.
```

## Deviations from the plan (verbatim from `DEVIATIONS`)

1. 2026-09-23, after the first build: the null verdict is written as 'null_result' instead of 'null', because pandas' CSV reader parses the string 'null' as missing, which made measured null results look like absent data in phase3_*.csv. The model status 'null' is written as 'null_result' for the same reason. Label change only; the rule is unchanged.
2. Process: the plan could not be written to a docs/ANALYSIS_PLAN_*.md file (the build harness blocks this contributor from writing new .md files with its editor), so it is the module docstring, written before the first verdict was computed; results/PHASE3_MEASUREMENT_EVIDENCE.md is generated by write_report().
3. Reporting additions after the first build (no rule changed): results/tables/phase3_rule_sanity_checks.csv (the plan's sanity checks as a table); a headline bullet listing condition reference verdicts that change under the pre-specified sensitivity thresholds (rx_migraine and rx_ibs); a second molecular table without post-hoc-flagged sources; verdict basis ('signature only' vs 'signature + pre-specified model') shown beside every verdict.
4. Independent review, 2026-09-23 (no verdict rule, threshold or reference label changed; every verdict is unchanged): (a) scope notes and headline flags now say that the post-infection-recovery verdicts rest on the ACUTE days 0..14 deviation only, with no verdict on return to baseline; that the ME/CFS-like proxy and functional_limitation activity differences are PARTLY DEFINITIONAL (the labels require self-reported activity limitation); and that rx_insomnia is drug-defined. (b) NHANES signal rows carry label-specific notes (rx reason-code drug caveat; definitional caveat). (c) The report states the rule's asymmetry (an untested label can be 'supported' while a tested null label is 'mixed'), the selection bias of 'best effect', and that the Uwakwe and rx_ibs sanity checks reproduce known producer conclusions and do not validate independently. (d) Bundle rows with no observable member no longer print the internal placeholder '__none__'; MapMECFS n is printed as an integer. (e) The dimension-grid figure draws UNKNOWN as hatched grey, not with the shade of a measured zero. (f) query.discover_candidate_measurements marks each demo-phenotype item with applies_to_queried_condition and a scope warning, because the Phase 3 reference label (e.g. rx_insomnia, the acute COVID-19 cohorts) is usually not a label for the queried condition.
5. 2026-09-23, integration item A8 (after the Phase 3 build): phenotype signatures were computed for the NHANES self-reported sleep labels SLQ050 (told a doctor about trouble sleeping) and SLQ060 (told of a sleep disorder), which the plan listed as an unanalysed gap. They enter as ordinary NHANES signal rows (label class self_reported_symptom_or_function; model not_tested) and in the 'other labels' of the sleep/circadian phenotype. No verdict rule, threshold or reference label changed; the sleep/circadian reference label stays rx_insomnia.
